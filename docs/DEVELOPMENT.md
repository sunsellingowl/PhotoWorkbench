# 开发与验证

PhotoWorkbench 是日常图片工具。用户说明在根目录 README；本文件保留构建、安全约定和验证边界。

## 构建

需要 Apple Silicon Mac、macOS 15 或更新版本、完整 Xcode 与 Python 3。当前只为 arm64 构建。固定的预编译引擎默认从 `/Applications/ImageOptim.app` **1.9.3** 复制，不会修改原应用；其他位置可通过 `IMAGEOPTIM_APP` 指定。引擎摘要必须与锁文件一致，不能直接用最新版替代。

```bash
bash run_build.sh
open dist/PhotoWorkbench.app
```

`run_build.sh` 自动调用 `scripts/run_prepare.sh`：首次下载 ImageOptim、libpng 固定源码和 PNGOUT 官方归档，应用补丁，复制引擎与许可证，并校验 SHA-256；依赖已准备好时只做本地校验。首次准备需要网络及指定版本的 ImageOptim，后续构建无需联网。Python 使用 `python3`，也可设置 `PYTHON=/path/to/python`。

补丁或锁文件变更后，旧 `vendor/` 不会被自动覆盖；先将它移到 `build/` 下备份，再重新构建。已有的下载缓存可以继续使用。

构建输出为 `dist/PhotoWorkbench.app`，日志为 `build/build.log`。成品含引擎及 Notices，不需要运行时 Python、Rust 或额外的 ImageOptim。签名仅为本机临时签名，不包含 Developer ID 或 Apple 公证，也不构成公开二进制发行许可核验。

也可在准备依赖后用 Xcode 打开 `PhotoWorkbench.xcodeproj`：

```bash
bash scripts/run_prepare.sh
open PhotoWorkbench.xcodeproj
```

添加原生源文件后运行 `python3 scripts/generate_project.py`，提交生成的工程文件。资源打包阶段显式声明引擎、Notices 和图标输出，确保增量构建更新资源后重新签名。图标生成使用像素尺寸的画布，仅缩放一次绘图坐标，防止小尺寸图层只在角落绘出一小块。图标源为 `scripts/make_icon.swift`，生成的 `native/AppIcon.icns` 是构建资源，随源码保留。

## 检查

安装 Pillow 到所选 Python 环境，然后运行：

```bash
python3 -m pip install Pillow
bash run_checks.sh
```

检查会构建应用、验证 ICNS 各图层的占比与居中、生成图片并运行原生验收。只使用生成图片，不访问个人图库；验证保存时会将生成图片的原件移入系统废纸篓。已有同一源码的构建时可用 `bash run_checks.sh --skip-build`。Clang 和 Swift 模块缓存默认保存在 `build/ModuleCache/`。原生验收覆盖创建时间的分钟命名、冲突与撤销、透明 RGB、16 位 PNG、EXIF/ICC 保留、各引擎、可选有损、损坏及只读文件、保存/引擎失败、备份丢失、外部改动、取消和 300 张图片批次。

当前套件 **129 项检查通过**，包含重构后新增的目录展开、目录符号链接和应用包跳过检查。0.9 初始验收曾有 117 项，包含已归档的上游输出比较；后续重构时也是 117 项，但范围不同。本轮新增分钟迁移、快速默认配置、ICC 内容变化和逐张进度检查。初始上游对比工具在 `v0.9` 标签和本机忽略的 `legacy/validation/` 中保留，当前检查不再编译或运行它，也不生成对比报告。

本机 macOS 27 / Xcode 27.1 上构建及签名检查通过。隔离 GUI 副本用生成图片验证了添加目录、PNG 压缩、WebP 跳过、原件恢复、改名、移出列表后撤销。此次未用真实鼠标拖放验证 SwiftUI URL 拖放入口；此前 GUI 验证还覆盖了设置切换、窗口尺寸、创建时间预览和 Quick Look。上述结果不代表 Intel、所有旧系统、网络盘或云同步竞争场景均已通过实机验证。

## 安全约定与限制

应用自有流程保持直接：目录入口统一筛选文件，SwiftUI 拖放直接传入 URL，撤销批次用数组保存，压缩只在准备阶段筛选和校验设置，收尾使用已准备的任务。内部数据按这些约定直接使用，不另加通用校验层。操作系统 I/O、引擎输出和运行期间的文件变化仍是独立边界，需报告真实错误并保留保存/恢复检查。

- 原生版仅使用文件创建时间和本机时区，格式为 `yyMMddHHmm.ext`。添加时缓存命名依据；自己的压缩和恢复后同步路径及签名，不接受未经核验的外部改动。
- 改名前预计算目标，执行独占移动。重入、权限、外部修改及撤销冲突必须检查，不覆盖图片、废纸篓条目或恢复文件。
- PNG 以 libpng 解码为不预乘、不做色彩转换的 RGBA16，比较全部像素的 SHA-256 摘要（含完全透明区域 RGB）；JPEG 使用同一路径的 ImageIO 解码和固定目标色彩空间比较。原图只生成一次指纹，候选各解码一次；保存直接使用已验证的不可变字节。
- 保留元数据时比较 PNG 附加块和 JPEG APP/COM 数据。ICC 比较解压后的完整配置字节（包含 ICC 内部名称和色彩数据）；忽略 PNG 容器的外部配置标签及 zlib 编码形式，因为 OxiPNG 会将标签 ICC 改为 icc 并重新压缩同一份配置。其他 PNG 附加块仍按原始内容比较。不能证明保留完整的候选被拒绝，不能仅因结果更小就保存。
- 同卷临时文件与原子交换用于保存；保留原件，废纸篓失败则回退，无法安全回退时给出恢复文件路径。Stop 仅取消剩余任务。
- Restore Originals 保留当前文件名，恢复成功后保留原废纸篓条目。退出清空列表与会话撤销历史，保留设置和窗口大小。
- 默认严格无损、优化力度 2、PNG 只启用 OxiPNG，保留元数据/日期/权限。PNGOUT、Zopfli、AdvPNG 和 PNGCrush 默认关闭，可显式开启；JPEGOptim 与 Jpegtran 继续开启。显式保存过的引擎设置不被新默认值覆盖。Guetzli 需要显式有损、JPEG 质量至少 85 及移除 JPEG 元数据，冲突时不自动修改设置。
- APNG 不压缩；单张解码缓冲超过 256 MiB 时拒绝压缩；非常规 JPEG 或无法完整验证的元数据会保守跳过。每次最多处理两张图片，像素解码串行且临时缓冲立即释放；缓存只保留摘要和元数据，不保留解码像素。
- 不启用跨会话结果缓存，不读取 ImageOptim 的共享设置或迁移旧缓存。上游源码有修改时必须同步补丁和锁定摘要，不直接升级引擎。
- ImageOptim 的缓存版本标记和 ResultsDb 源码保持上游原样；本应用用 `resultsDatabase:nil` 创建 Job，不实例化该缓存。补丁只保留应用内引擎定位、严格像素与元数据要求，以及已验证必要的调度、取消和引擎失败处理。

## 性能排查与回归

当前行和完成数随单张任务结束更新，不再等整批结束。正在计算时仅在状态文字发生变化后发布列表变更，避免定时器每 0.2 秒重绘相同内容。完成后的行不再显示上游遗留的 Started / Waiting 文案。文件签名使用保存时的已提交快照；下一次修改或恢复之前仍验证磁盘文件，没有把外部改动接受为自己的结果。

可在构建后运行 `bash scripts/benchmark_compression.sh`，用 4 张生成图片测快速配置；第二个参数可选 fast / deep，第一个参数可指定对应版本的原生对象目录。基准不处理个人图片。记录墙钟时间、进程与引擎累计 CPU 时间和输出字节；CPU 时间是开销指标，不是瓦数测量，单张合成图也不代表所有图片。

### 本机性能参考（2026-11-07）

相同的 4 张 1024×768 生成 PNG，每种配置独立运行三次，取中位数：

| 后端 / 配置 | 墙钟时间 | 累计 CPU 时间 | 输出总字节 |
| --- | ---: | ---: | ---: |
| 旧后端 / 深度默认 | 7.282 s | 26.555 s | 17,288 |
| 旧后端 / 快速配置 | 0.269 s | 0.616 s | 18,340 |
| 新后端 / 相同深度配置 | 7.244 s | 25.970 s | 17,288 |
| 新后端 / 快速默认 | 0.240 s | 0.589 s | 18,340 |


相同深度配置的引擎计算量没有消失。快速默认通过避免昂贵的引擎组合获得主要收益，本例输出体积增加约 6.1%；不能据此承诺真实图片达到相同比例的加速，也不能将 CPU 累计时间当作瞬时功耗。本轮原生 129 项检查和 ICNS 十个图层检查通过；解锁后已在 About 窗口目视确认图标比例。后续按钮布局调整通过构建和签名检查，并用隔离 GUI 副本及生成 PNG 确认默认窗口中的左右分组、蓝色 Rename / Compress 和分钟级名称预览；该界面调整未重跑压缩验收。

## 发布边界

GitHub 源码仓库与可下载的应用发行附件是两件事。目前未上传应用发行附件。发布捆绑二进制前，需要逐一核对引擎再分发许可，并准备 GPL 组件的对应源码及构建资料。单靠本仓库的下载地址、摘要或“尊重版权”声明不能代替这些工作。PNGOUT 不属于 GPL，ImageOptim 自己取得的捆绑许可不自动授权本项目。
